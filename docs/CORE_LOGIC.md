# Core logic

## お手伝い

### 選択と一括追加

`tasks` が候補リスト、`todayTasks` が今日のリストです。個別追加、チェック式一括追加、`taskHistory` 検索からの追加があります。同じ `taskId` は二重追加されません。履歴検索では `title::category` が同じ今日項目も重複扱いです。追加時は報酬情報を `TodayTask` にコピーします。

### 完了

現行UIは開始操作を持たず、今日の未完了カードから直接 `completeTask` を呼びます。

1. TaskとTodayTaskが存在し、TodayTaskが未完了か確認。
2. `status = done`、`completedAt` を設定。
3. 最新Taskの報酬タイプ・枚数をTodayTaskへ再設定。
4. `ticketGranted` がfalseの場合だけ `coins` または `starCoins` を加算しtrueへ変更。
5. `taskHistory` の完了回数と `history` を更新し保存。

関数冒頭の完了判定と `ticketGranted` の二段階で、同じTodayTaskに対する通常操作での二重付与を防止します。

### キャンセル／リセット

未完了項目だけ、確認後に `todayTasks` から除外できます。手動リセットは確認後に全TodayTaskを空にします。自動リセットは午前6時を境界に1日1回行い、一般履歴へ `dailyReset` を追加します。完了済み項目も今日の配列から消えますが `taskHistory` と一般履歴は残ります。

## チケットとスターコイン

- チケット残高は `state.coins`。名称が `ticket` ではない点に注意。
- スターコイン残高は `state.starCoins`。
- 親の直接プレゼントは1/2/3/4/5/10枚から選択し、確認画面後に加算。`ticketGiftLogs` と一般履歴へ記録。
- ありがとうスターは空でない40文字以内のメッセージとブラウザ確認後、常に1枚加算。親パスワードは不要。
- 5スター交換は `starCoins >= 5` が条件。5減算、チケット1加算、`starCoinExchange` を記録。5未満はボタンdisabledで、関数側にも不足ガードあり。

## ルーレット

### BETと不足制御

BETは1〜5。回転開始時に `coins < activeBet` なら停止し、不足枚数を表示します。開始時にBET分を即時減算します。予約済みハピチャンカードも開始時に1枚消費します。

### 重み付き抽選

`weightedPick` は全weight合計に対する `Math.random()` で抽選します。

| BET | 枠（ポイント:重み） | 合計weight |
|---:|---|---:|
| 1 | 1:5, 2:3, 通常0:2, ハピチャン:2 | 12 |
| 2 | 2:5, 4:3, 通常0:2, ハピチャン:2 | 12 |
| 3 | 3:4, 5:3, 8:2, 通常0:1, ハピチャン:2 | 12 |
| 4 | 4:4, 8:3, 12:2, 通常0:1, ハピチャン:2 | 12 |
| 5 | 5:4, 10:3, 15:2, 20:1, 通常0:1, ハピチャン:2 | 13 |

通常ポイントは選択中の `points.snack|toy|game` に加算します。通常0P枠はチケットを1枚返します。ハピチャン枠は0Pでカードを1枚加算します。予約カードは抽選結果に関係なく+1Pです。

`useHappyChanceCard` という結果後使用ロジックも残っていますが、現在の抽選結果は常に `canUseCard: false` で生成されるため、現行UIから実行されません。現在利用できるのは抽選前の予約方式です。

## PAYとごほうび

- ルーレットで SweetsPAY=`points.snack`、ToyPAY=`points.toy`、GamePAY=`points.game` を加算。
- ごほうび画面で1以上の整数を入力し、残高以内なら減算。`payLogs` と一般履歴へ記録。
- 親画面で異なるPAY間を1P以上、残高以内で1:1振替。確認ダイアログ後、元から減算して先へ加算。合計は不変。
- 商品・価格マスタはなく、ハピチケSHOPの交換は任意ポイントの使用記録です。

## 親管理

右下の「おうちの人用」または一括選択内の「おうちの人用 編集する」から、保存済み平文パスワードとの文字列比較で解除します。管理メニューではお手伝い追加・編集・削除、報酬枚数一括変更、PAY振替、チケット付与、親メール保存ができます。親認証はセッションやサーバー認証ではなくモーダル内の簡易ロックです。

## ログ追加と表示

`addHistory` は先頭追加して40件に切り、直ちに `saveState()` します。きろく画面は以下の3区分です。

- PAY交換ログ: `payLogs` と `transferHistory` を配列順に連結して表示
- お手伝いかんりょうきろく: `history` から完了typeまたは旧文面パターンを抽出
- ぜんぶのきろく: `history` 全件をtype別または一般文面で表示

PAY使用・振替はそれぞれ専用ログと一般履歴の両方に入り、完了ログも2区分に重複表示されます。

## メール共有／外出用カード

親メールが妥当な形式なら、名前、3種PAY、チケット、スターコイン、ハピチャンカード、作成日時を本文にした `mailto:` URLを開きます。送信処理・画像生成・送信結果確認はありません。メール作成画面を開いた時点で `hapichikeCardEmailShared` を記録します。
