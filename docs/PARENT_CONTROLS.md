# Parent controls

## 入口とロック

通常画面右下の「おうちの人用」ボタンから親管理モーダルを開きます。もう1つの入口は「お手伝いを選ぶ」モーダル内の「おうちの人用 編集する」です。どちらも `state.parentPassword` と入力文字列を比較します。

初期パスワードは `1234`。localStorage主状態内に平文で保存され、変更UI、ハッシュ、試行回数制限、タイムアウト、サーバー検証はありません。本格認証ではなく、同じ端末の子どもによる誤操作を減らす簡易ロックです。

## 親管理でできること

- お手伝い候補の追加・編集・削除
- 名前、カテゴリー、難易度、アイコン、報酬タイプ、1〜5枚の報酬設定
- 全候補の報酬枚数だけをまとめて変更
- SweetsPAY / ToyPAY / GamePAY間の振替
- チケット1〜10枚の直接プレゼントと理由メモ
- 外出確認用カードに使う親メールの設定

## 通常画面との分離

追加・編集・削除ボタンは通常のお手伝いカードには表示されません。一括選択内でもパスワード解除前は選択だけです。ただし、次の状態変更は親ロック外にあります。

- ありがとうスター付与
- PAYポイント使用
- 履歴削除
- 今日の状態リセット
- 子どもの名前変更
- お手伝い完了／キャンセル、ルーレット

これらを子どもに許可するかはコードからは判断できないため、要確認です。特にありがとうスターはスターを自己加算でき、5枚でチケットへ交換できます。

## セキュリティ境界

localStorageと画面コードを読める利用者からデータを保護するものではありません。機密情報・強い本人確認・複数保護者権限として扱わないでください。

## Supabase Authの閲覧専用画面

親は `/parent` でemail/passwordのSupabase Authへログインし、所属家庭と子どもを切り替えて残高・最近のお手伝い・reward logを閲覧できます。ログインuserは`household_members`の`owner`または`parent`として家庭に所属し、RLSにより所属家庭だけを取得します。子どもはAuth userにせず`children`プロフィールとして管理します。

この認証は現在の`state.parentPassword`による簡易ロックとは別です。簡易パスワードは削除・変更・移行せず、Supabaseの`parent_settings`にも保存しません。`/parent` は閲覧専用で、付与・編集・削除・同期ボタンを持ちません。localStorageをデータソースにせず、書き込みも行いません。member招待/受諾と両ロックの役割整理は今後のタスクです。
