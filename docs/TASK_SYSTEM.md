# Task system

## データの役割

- `tasks`: お手伝い候補ライブラリ。初期6件と親が追加した項目。
- `todayTasks`: 今日選んだ項目。`taskId` で候補を参照する。
- `taskHistory`: 過去に使った候補の検索用スナップショット。
- おわった一覧: 独立保存ではなく、`todayTasks` の完了項目を抽出。

## カテゴリー・難易度・報酬

カテゴリーは生き物、りょうり、洗だく、片つけ、そとのお仕事の5種です。難易度は easy / normal / hard。報酬タイプはticket / starCoinで、各報酬枚数は1〜5です。アイコンは候補選択または入力でき、保存時に先頭の1書記素を採用します。

## 今日の流れ

1. 「お手伝いを選ぶ」で複数選択、候補一覧から個別追加、または履歴検索から追加。
2. `todayTasks` に未完了・未付与状態で追加。
3. 現行UIでは開始段階なしで「お手伝い完了！」を押す。
4. 完了報酬と履歴を保存し、「おわった」へ表示。
5. 未完了項目は確認後にキャンセル可能。
6. 午前6時境界または手動リセットで今日の配列を空にする。

## 新規追加・編集

親管理画面の「お手伝い編集」から追加できます。また「お手伝いを選ぶ」内で親パスワードを通過し、親編集モードに入ると直接追加・編集・削除できます。追加に必要なのはお手伝い名、アイコン、カテゴリー、難易度、報酬タイプ、選択中報酬の枚数です。タイトルは必須、カテゴリー・難易度・両報酬枚数はコード側で検証します。

保存先は主localStorage内の `tasks`。追加自体は既存候補を変更しません。編集は同じIDの候補を書き換え、完了時には最新候補の報酬をTodayTaskへ再コピーします。削除は `tasks` と該当 `todayTasks` から消しますが `taskHistory` と一般履歴は残ります。

## 状態上の注意

`status`, `startedAt`, `completedAt`, `ticketGranted` を保持しますが、現行UIで `startedAt` を設定する操作はありません。`ticketGranted` はスター報酬にも共用されます。詳細は `DATA_STRUCTURE.md` と `CORE_LOGIC.md` を参照してください。
